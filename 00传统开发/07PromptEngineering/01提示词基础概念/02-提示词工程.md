# 提示词工程（Prompt Engineering）完整整理

## 一、什么是 Prompt（提示词）

提示词是用户给到大语言模型 LLM 的文本，本质是**上下文 + 指令**，也就是给 AI 的问题、指令。

> ⚠️关键区别：Prompt 属于临时指令，**不会改变模型本身**；Fine‑tuning（微调）会修改模型权重，属于长期生效。企业开发一般两者结合使用。

示例：

- “帮我写一首诗”
- “用小学生听得懂的话解释黑洞”

Prompt 三大核心要素：

1. **指令**：要模型做什么
2. **上下文**：背景信息
3. **格式要求**：输出要长什么样

提示词质量直接决定输出质量：提示词差，输出混乱出错；提示词工程就是专门研究如何写好提示词的领域。

> Prompt 分为**系统提示词、用户提示词**，是人类和 LLM 交互的唯一入口，上层大模型应用本质都是拼接构造高质量 Prompt。

Prompt 组成元素对照表

表格

| 元素     | 说明                 | 例子                         | 备注             |
| -------- | -------------------- | ---------------------------- | ---------------- |
| 指令     | 要执行的核心动作     | 总结、翻译、写代码           | 必须明确         |
| 背景     | 外部上下文、身份场景 | 我是 Java 初学者、三年级学生 | 限定模型视角     |
| 角色扮演 | 让模型扮演特定身份   | 扮演健身教练、架构师         | 属于背景的一类   |
| 输入     | 待处理原始素材       | 待总结文本、题目、数据表     | 处理原材料       |
| 输出     | 格式、长度、样式     | JSON、Markdown、1000 字      | 控制返回结果形态 |

## 二、提示词工程 Prompt Engineering

> 定义：以工程化思路设计、优化提示词，最大化释放大模型能力，拿到符合预期的高质量输出。 作用：提升任务准确度、相关性、创造力。

### 2.1 工程化编写提示词实操技巧

#### ① 清晰明确的指令

避免模糊歧义，直接说明任务；可以使用引号、冒号、分隔符区分任务要求和用户输入。

> 示例递进：

1. 生成一篇最新科技进展文章（模糊）
2. 以量子计算为主题，生成一篇科技新闻文章（明确主题）
3. 以量子计算为主题，重点强调对未来技术的影响，生成深度科技报道（完整要求）

#### ② 给模型 “思考时间”（比喻义）

提供充足背景细节，复杂任务引导分步输出。

- 方式 1：补齐背景细节（旅游行程案例）
- 方式 2：强制分步计算、分步推导（数学应用题分步解题）

#### ③ 使用分隔符隔离指令与待处理文本

用`###` / `"""`把用户原始素材包裹，防止文本内容污染指令。 ✅正确示例：

> 将下面用三个引号括起来的内容翻译成英文。 """锦瑟无端五十弦，一弦一柱思华年"""

#### ④ 指定输出格式

强制模型按照指定格式返回，常用：Markdown、JSON、Mermaid、PlantUML、思维导图模板、自定义文本模板。

#### ⑤ 角色扮演

给模型设定身份、专业背景，大幅提升输出贴合度。

表格

| 差提示词         | 优化后提示词                                                 |
| ---------------- | ------------------------------------------------------------ |
| 给我一个减肥计划 | 你是专业健身私教，结合运动科学与营养学，为我定制一份减肥计划 |

#### ⑥ 专业化 Prompt 五层结构模型

表格

| 层级   | 名称 | 核心内容                       |
| ------ | ---- | ------------------------------ |
| 第一层 | 角色 | 角色身份、能力背景             |
| 第二层 | 场景 | 需求、业务目标                 |
| 第三层 | 任务 | 可执行的任务清单               |
| 第四层 | 示例 | 样例、正反案例、输出模板       |
| 第五层 | 约束 | 限制条件、红线、偏好、规避风险 |

通用模板：`Prompt = 角色 + 任务 + 要求 + 细节`

```
提示词1：
	角色：你是一个 10 年的 python 开发工程师，可以按照需求撰写代码，帮我解决 bug；
	任务：写一个爬虫代码，爬取网页版抖音的热搜视频。
	要求：要求生成代码简洁，每行代码编写注释；爬取的单个视频进行压缩不能超过100M。
	限制：限制代码不超过200行
	
提示词2：
	角色：资深主流媒体新闻撰稿人，拥有8年民生行业新闻采编经验，擅长客观中立撰写社会新闻，熟悉新闻写作规范，懂得区分事实与主观评价。
    任务：根据提供的事件素材，产出一篇标准新闻稿件。
    写作要求：
        1. 严格遵循新闻文体结构：标题、导语、正文、结尾；标题简洁概括事件核心，导语交代时间、地点、人物、事件、起因、结果六要素。
        2. 行文客观写实，以陈述事实为主，逻辑清晰，段落分层合理，语句通顺，符合大众阅读习惯。
        3. 适当引用当事人、相关方的模拟采访语录，增强新闻真实感。
        4. 全文字数控制在600‑800字。
    细节规范：
        1. 标题：主标题+简短副标题，主标题直击事件，副标题补充背景信息。
        2. 导语放在文章第一段，必须把核心信息全部浓缩。
        3. 正文分段叙事：事件经过→各方情况说明→现实影响→后续进展。
        4. 采访对话使用引号包裹，人物身份标注清晰。
        5. 结尾客观陈述后续展望，不强行升华鸡汤。
    硬性限制：
        1. 禁止编造不存在的官方机构、人名、具体时间地点；没有给到的素材信息不得凭空杜撰。
        2. 不使用夸张网络热词、表情包、情绪化煽动语句，拒绝主观褒贬、带节奏。
        3. 不输出虚构的处罚结果、官方通报，没有素材支撑绝不下结论。
        4. 不加入笔者个人感想，全部以新闻第三方视角输出。
        5. 禁止出现低俗、敏感、违规内容。
        用户接下来会给到事件素材，你依据以上全部规则生成新闻稿。
```



### 2.2 推理模型（深度思考模型）提示写法

> 代表模型：o1、DeepSeek‑R1、通义 QwQ、豆包深度思考模式 类比：能力很强，但不知道你的业务细节的员工。 ✅写法：`角色 +（可选背景）+ 目标`，**不要手把手教步骤，交给模型自主推理**。

实用小技巧：

1. 补充提问者身份背景，例如 “我是初学者”，输出会降低理解门槛；
2. 观察模型思考过程，可以看到模型推理逻辑；
3. 可以用强推理模型生成 Prompt，再放到普通模型执行。

## 三、进阶提示词技术

### 3.1 Zero‑Shot 零样本提示

不给任何样例，仅凭指令，依靠模型原生知识完成任务。

- ✅优点：上手简单；❌缺点：小众复杂任务准确率低
- 适用：翻译、简单改写、常识问答、基础总结
- 不适用：小众分类、高精度标注

### 3.2 Few‑Shot 少样本提示

提供少量示范样例，让模型模仿样例的格式、逻辑、风格完成新任务。

- 原理：用样例给模型定规则，不需要微调模型，低成本提升效果
- ✅适用：自定义分类、固定格式生成、特殊提取规则；❌不适用：海量样本场景（适合微调）

### 3.3 CoT 思维链（链式思考）

不让模型直接输出答案，强制分步拆解问题，输出中间推理步骤，再给出最终结果。

- 解决：数学计算、逻辑推理、复杂阅读理解，减少一步直答带来逻辑错误
- ❌不适合：简单翻译、短句分类（浪费 token）

### 3.4 Self‑Consistency 自我一致性

基于 CoT，生成**3‑5 条不同推理路径**，多条答案投票，取出现最多的结果作为最终答案。

- 强项：数学、多步骤业务计算；❌不适合：文案创作、翻译，消耗 token 高

### 3.5 ToT 思维树

在思维链每一步生成多个思考分支，模拟迷宫探索；对分支做评估剪枝，淘汰错误路径，保留优质分支继续推导，收敛最优解。

- 四步：拆分节点→发散分支→评估剪枝→回溯择优
- ✅适用：复杂规划、谜题、代码推导、博弈决策；❌简单任务不推荐

> 速记总结
>
> - Zero‑Shot：直接答
> - Few‑Shot：照着例子答
> - CoT 思维链：单条路径分步推
> - Self‑Consistency：多条路径投票择优
> - ToT 思维树：多分支探索、剪枝找最优解

## 六、Prompt 攻击与工程防范

### 6.1 提示词注入攻击

恶意构造输入，劫持模型，篡改系统设定、越狱突破安全限制、泄露系统提示词。 常见攻击类型：

1. **前置覆盖攻击（指令劫持）**：忘记前面所有设定，强制替换系统规则
2. **越狱 Jailbreak**：诱导输出违规、黑灰产内容
3. **隐写 / 拼接注入**：恶意指令藏在长文本、乱码、markdown 中
4. **间接注入**：知识库、网页文档携带恶意 prompt，后台被劫持
5. **DAN 角色扮演越狱**：通过剧情演戏绕过安全机制

危害：泄露内部提示词、生成恶意代码 / 诈骗话术、业务逻辑被篡改。

### 6.2 工程落地防范方案

1. **输入层过滤**：正则拦截越狱关键词，截断超长恶意拼接、乱码隐写内容
2. **指令隔离（核心）**：系统提示词和用户输入用固定分隔符严格隔离，用户输入无法侵入系统指令域
3. **模型侧安全加固**：开启厂商内置安全风控，安全对齐微调
4. **知识库净化**：不直接加载外网不可信文本，入库前清洗注入特征
5. **资源限制**：限制输入长度、推理时长、token 资源消耗

## 七、面试题：Prompt Engineering 如何驾驭大模型

> 答题四维度：概率坍缩、ICL 上下文学习、算力资源分配、工程落地

1. 底层原理
   - 概率坍缩：大模型本质是概率预测机器；角色、背景提示会压缩概率空间，把输出约束到指定领域。
   - ICL 上下文学习：Few‑Shot 样例触发上下文学习，唤醒模型已有能力，不是训练新知识。
   - 算力分配：CoT 等提示，通过输出中间步骤，用 token 空间换取推理精度。
2. **进阶战术**：CoT 单步链式推理；ToT 多分支探索剪枝；ReAct 实现思考 + 工具调用闭环，实现智能体。
3. 工程实践
   - 解决幻觉：RAG 检索增强生成，绑定外部事实资料；
   - 对抗 Prompt 脆弱性：自动化 Prompt 优化；
   - 效果评估：LLM‑as‑a‑Judge 大模型自动打分。

> 答题可以从信息论（概率坍缩）、认知（ICL）、算力（推理步骤）、工程（RAG、评估）四个角度组织回答。
