# RAG 检索模块复习提纲 & 面试速记卡

## 一、一条完整演进主线（背这条就够）

**一句话串起来**：One-Hot 没语义 → Word2Vec 给语义但静态 → FastText 补 OOV → BERT 补上下文但不会做句向量 → SBERT 补句向量 → 现代 Embedding 用对比学习规模化 → 支撑 RAG 检索。

## 二、四张速记卡

### 卡 1｜概念辨析（最容易被问"区别"）

| 对比 | 关键区别 |
|------|----------|
| **静态 vs 动态向量** | 静态：一词一向量（Word2Vec/FastText）；动态：随上下文变（BERT） |
| **Word Embedding vs 语言模型** | 词嵌入=静态向量表示；语言模型=动态概率预测模型，用词嵌入做输入 |
| **BERT vs SBERT** | BERT 擅长理解、输出 Token 级向量；SBERT 专门产出句子向量做相似度 |
| **BERT vs Embedding 模型** | BERT 是"理解器"，Embedding 模型是"文本→向量转换器"，SBERT 是现代 Embedding 起点 |
| **Embedding vs Rerank** | Embedding 管**召回**（海选 Top20，要快要广）；Rerank 管**排序**（精挑 Top3，要准可慢） |
| **One-Hot vs Embedding** | One-Hot 稀疏巨大无语义；Embedding 低维稠密、语义守恒 |

### 卡 2｜核心原理（面试必考）

**1. Embedding 五大特点**
低维稠密 / 连续可微 / **语义守恒（灵魂）** / 可计算 / 隐式特征提取

**2. 语义守恒经典例子**
- 国王 − 男人 + 女人 ≈ 王后
- 北京 − 中国 + 日本 ≈ 东京

**3. Self-Attention 一句话**
处理一个词时，让它关注句子里所有其他词（"苹果"关注"手机"→ 判定为公司而非水果）。

**4. BERT 两个预训练任务**
- **MLM（掩码语言模型）**：挖空猜词，学上下文关系
- **NSP（下一句预测）**：判断两句是否连续，学句间关系

**5. 现代 Embedding 训练方法：对比学习**
- 正样本拉近（"如何申请退款"↔"退款流程说明"）
- 负样本推远（"如何申请退款"↔"北京天气"）

**6. 余弦相似度**
- cos(u,v) = (u·v) / (||u||·||v||) 越接近 1 越相似（只看方向不看长度）

**7. RAG 流程**
-问题 → Embedding → 向量检索 → 召回文档 → （Rerank）→ LLM → 答案

### 卡 3｜模型选型（企业场景题）

| 场景 | 推荐 | 理由 |
|------|------|------|
| 创业公司/快速验证 | OpenAI Embedding | 效果好、API 简单、开发快 |
| 私有化部署 | BGE-M3 / GTE-Qwen2 | 可本地部署、开源 |
| 中文知识库 | BGE-M3 | 中文能力强、RAG 首选 |
| 多语言知识库 | OpenAI / GTE / Jina | 多语言优秀 |
| Qwen 生态项目 | Qwen Embedding | 与 Qwen 协同 |

**BGE-M3 的"3M"**：Multi Function（稠密/稀疏/混合检索）、Multi Lingual（多语言）、Multi Granularity（短/长文本）。

**评测指标（企业必测）**：
- **Recall@K**：TopK 是否召回正确答案
- **MRR**：正确答案排第几
- **Latency**：速度
- **Cost**：成本

**维度误区**：不是越高越好。高维表达强但存储×4、检索慢、成本高；**768/1024 维企业已足够**，以实测 Recall@K/MRR 为准。

### 卡 4｜面试 Q&A 速答（直接背）

| 问题 | 答案 |
|------|------|
| Word2Vec 最大缺陷？ | 静态向量，无法理解上下文（"苹果"永远同一向量） |
| BERT 最大创新？ | 双向上下文理解，产出动态向量 |
| 什么是 Self-Attention？ | 一个词关注句子中所有词，吸收上下文 |
| 什么是动态向量？ | 同一个词，不同上下文，不同向量 |
| 为什么说现代 Embedding 建立在 BERT 基础上？ | 都基于 Transformer，继承上下文表示思想 |
| Embedding 本质？ | 文本在高维空间中的语义表示（文本→向量转换器） |
| 为什么 BERT 不能直接做向量检索？ | 擅长理解，不擅长句向量表示（输出 Token 级向量） |
| SBERT 解决什么问题？ | 句子级 Embedding，专用于相似度计算 |
| RAG 中 Embedding 的作用？ | 负责召回相关知识，决定召回质量 |
| 为什么企业要评测 Embedding？ | 不同模型召回率差异巨大，不能盲选 |
| Embedding 和 Rerank 区别？ | Embedding 召回（快广），Rerank 排序（准慢） |

## 三、三个"送分案例"（能讲清楚就赢一半）

**案例 1：一词多义**
- "苹果很好吃" → 苹果向量接近香蕉/橘子
- "苹果手机很好用" → 苹果向量接近华为/小米
- 原因：Self-Attention 让"苹果"关注"手机"，动态调整向量。

**案例 2：语义检索跨关键词**
- 问"订单怎么退" ↔ 文档"退款申请流程"
- 关键词不同但语义近，Embedding 通过上下文理解实现召回。

**案例 3：100 万文档选 768 还是 3072 维**
- 性能：3072 存储×4、检索慢
- 成本：存储/内存/推理都更高
- 召回率：取决于模型训练质量而非单纯维度
- 结论：**优先 768/1024，用 Recall@K/MRR 实测，不盲目追高维**。

## 四、易错点提醒（踩坑清单）

1. ❌ "BERT = Embedding" → ✅ BERT 是理解器，SBERT 才是句向量起点。
2. ❌ "维度越高越好" → ✅ 768/1024 通常够用，看实测。
3. ❌ "Embedding 负责排序" → ✅ Embedding 召回，Rerank 排序。
4. ❌ "词嵌入能理解上下文" → ✅ 静态词嵌入不能，BERT 类动态模型才能。
5. ❌ "RAG 只靠 Embedding" → ✅ 完整链路是 召回(Embedding) + 排序(Rerank) + 生成(LLM)。
